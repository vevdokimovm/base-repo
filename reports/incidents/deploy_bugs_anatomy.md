# Разбор багов деплойера: пять находок

**Дата:** 2026-07-24 · **Объект:** `templates/deploy.sh`
**Как найдены:** 1 и 4 — локальными тестами до боевого прогона; 2 — анализом истории сбоев;
3 — боевым прогоном на реальных архивах.

> Ценность этого документа не в списке фиксов, а в **анатомии**: каждый баг относится к классу,
> который повторится в другом месте. Классы важнее конкретики.

## PIT-014 — тег указывает на дерево предыдущей версии

**Класс:** доверие к кэшу вместо содержимого.
**Симптом:** серия версий публикуется, теги стоят, но `git show v1.1.0:VERSION` отдаёт `1.0.0`.
Внешне всё зелёное — расхождение видно только если специально проверить.

**Механика.** Дерево копируется в клон через `cp -a`, который **сохраняет mtime** исходных файлов.
У архивов одной серии, собранных подряд, mtime совпадает. Файл `VERSION` вдобавок одного размера
(`1.0.0` и `1.1.0` — пять байт). Git при индексации сверяет пару **size + mtime** (stat-кэш) и,
если она не изменилась, **не хэширует содержимое** — считает файл неизменённым. Итог: дерево на
диске новое, индекс пуст, коммита нет, тег вешается на старый коммит.

**Фикс.** Индекс пересобирается принудительно, а не по stat-кэшу:

```bash
git rm -r --cached -q . >/dev/null 2>&1 || true
git add -A -f
```

**Контроль.** Тест 2: три версии с принудительно одинаковым mtime (`touch -t`), проверка
`git show vX:VERSION == X` для каждой. Плюс тест 18 на порядок версий.

**Урок класса.** Любой инструмент, оптимизирующий работу по метаданным, врёт, когда метаданные
подделаны копированием. Если содержимое критично — заставляй перечитывать содержимое.

## PIT-015 — «архив не пушится» из-за упаковки

**Класс:** защита, отключающаяся от постороннего мусора.
**Симптом:** нерегулярный, годами. Иногда архив разворачивался нормально, иногда в репу уезжало
дерево, вложенное в папку `<repo>-vX.Y.Z/`, либо скрипт отказывался работать.

**Механика.** Разворот папки-обёртки срабатывал по условию «в корне архива ровно один объект, и это
папка». macOS при архивации кладёт рядом `__MACOSX/` и `.DS_Store`. Тогда объектов в корне два или
три — условие ложно, обёртка не разворачивается, а маркер корня (`README.md`) на этом уровне
отсутствует. Дальше по обстоятельствам: либо отказ, либо вложенное дерево в репе.

**Фикс.** Мусор ОС удаляется **до** проверки обёртки, а сам разворот стал циклом до 3 уровней
вглубь — пока не найдётся `README.md`.

**Контроль.** Тест 5 (мусор рядом с обёрткой), тест 19 (плоская упаковка), тест 20 (двойная
обёртка).

**Урок класса.** Порядок «очистка → проверка» вместо «проверка → очистка». Проверка, которую можно
сбить посторонним файлом, — не проверка. Зафиксировано стандартом `43`.

## Потеря правки `repos-map.md`

**Класс:** запись в эфемерное хранилище.
**Симптом:** скрипт бодро отчитывался `✓ repos-map обновлена`, но в карте ничего не появлялось.

**Механика.** Клон base-repo искался по списку кандидатов, куда входила и рабочая папка прогона
(`$WORK/base-repo`) — временный клон, созданный для деплоя самого base-repo. Если base-repo
публиковался в том же прогоне, карта обновлялась именно в нём: **после** push и **перед** удалением
рабочей папки. Правка исчезала вместе с папкой.

**Фикс.** В кандидатах только постоянные клоны, путь внутри `$WORK` отбрасывается явно. Если
постоянного клона нет — текст не теряется, а пишется в `~/Downloads/repos-map-additions.md`,
и поднимается громкий флаг.

**Контроль.** Тест 15: base-repo и новая репа в одном прогоне; проверяется, что текст оказался
на диске и что во временный клон не писали.

**Урок класса.** Найден **только боевым прогоном** — юнит-тест такого не показывал, потому что
проблема в жизненном цикле окружения, а не в логике. Отсюда правило: полный прогон на реальных
данных обязателен даже при зелёных тестах.

## Пустая репа-сирота на GitHub

**Класс:** необратимое действие раньше проверки.
**Симптом:** битый или неполный архив → репа на GitHub уже создана → публиковать в неё нечего →
остаётся пустая репа, которую надо удалять руками.

**Механика.** Порядок шагов: создать репу → склонировать → распаковать архив → проверить. Проверки
корня, количества файлов и совпадения `VERSION` стояли **после** создания.

**Фикс.** Предполётная проверка на этапе инвентаризации, по списку файлов внутри zip
(`unzip -Z1`, без распаковки — дёшево даже для архива на 7000 файлов): читается ли архив, есть ли
`README.md`, достаточно ли файлов, совпадает ли `VERSION` с версией в имени. Не прошедший архив
выбывает **до** любого обращения к GitHub.

**Контроль.** Тест 21 (мало файлов), тест 7 (нет README), тест 8 (VERSION≠имени), тест 22 (битый
zip не роняет батч).

**Урок класса.** Все проверки, какие возможны, — до первого необратимого действия. Порядок
операций сам по себе является защитой.

## Склейка версий при вложенной репе

**Класс:** глоб шире, чем намерение.
**Симптом:** архив `dota-dossier-v2.13.0.zip` отвергнут с сообщением
`VERSION в дереве = 1.13.02.13.0`. Такой версии не существует — это два числа, слипшиеся в одно.

**Механика.** Предполёт читал версию из архива глобом `unzip -p "$z" '*/VERSION'`. После того как
`base-repo` был интегрирован **внутрь** `dota-dossier`, в архиве стало два файла `VERSION`:
корневой (`2.13.0`) и вложенный (`base-repo/VERSION` → `1.13.0`). Глоб совпал с обоими, `unzip -p`
вывел их подряд, а поскольку в `VERSION` нет завершающего перевода строки, `head -1` увидел одну
строку из двух склеенных чисел.

**Фикс.** Версия читается строго по корневому пути: сначала определяется папка-обёртка (если в
корне архива ровно один объект), затем берётся именно `<обёртка>/VERSION`. При плоской упаковке —
`VERSION` в корне. Вложенные репы больше не попадают под выборку.

**Контроль.** Тест 31: репа с вложенной репой, у каждой свой `VERSION`; проверяется отсутствие
склейки, успешная публикация и сохранность вложенного дерева.

**Урок класса.** Найден на **финальной приёмке собственного артефакта** — скрипт отверг архив,
собранный этим же проектом. Случай показателен вдвойне: во-первых, глоб `*/X` почти всегда шире
намерения, и путь надо адресовать точно; во-вторых, приёмка «прогони инструмент по своему же
результату» ловит то, что не ловят ни тесты, ни код-ревью.
