# `deploy.sh` — контракт (чёрный ящик)

> **Зачем этот файл.** Описывает, **что** скрипт гарантирует, а не **как** он это делает.
> Когда нужно поменять поведение — сначала правится контракт, потом код и тесты.
> Если правка не описывается в терминах этого файла, значит она непонятна и пользователю.
>
> Режимы и ключи — `deploy-MODES.md`. История изменений — `deploy-CHANGELOG.md`.
> Правило одного скрипта — `README.md`.

---

## 1. Назначение одной фразой

**Взять zip-архивы версий из папки и привести GitHub в состояние, где у каждой версии есть
коммит, тег и релиз по стандарту.**

Всё остальное в скрипте — следствие этой фразы.

---

## 2. Вход

| Что | Откуда | Обязательность |
|---|---|---|
| Архивы `<repo>-vX.Y.Z.zip` | папка (по умолчанию — где лежит скрипт) | да |
| Состояние GitHub | `gh` + git | да |
| `CHANGELOG.md` внутри архива/репы | секция версии | да, иначе релиз не создаётся |
| Флаги режимов | переменные окружения | нет, у всех есть дефолт |
| `repos-map.md` | base-repo на GitHub | только для `ALL_REPOS=1` |

---

## 3. Выход: что обязано быть после успешного прогона

Для **каждой опубликованной версии** — все пять пунктов, иначе версия считается
незавершённой и попадает в отчёт об ошибках:

1. **Коммит** в `main` с деревом ровно из архива, сообщение `<repo> vX.Y.Z — <тезис>`.
2. **Тег** `vX.Y.Z`, указывающий на этот коммит (а не на соседний).
3. **Релиз** с заголовком `<repo> vX.Y.Z — <тезис>`.
4. **Тело релиза** = секция версии из `CHANGELOG.md`, шапка нормализована к `## [X.Y.Z]`.
5. **Канонический ассет** `<repo>-vX.Y.Z.zip` — из архива, а если архива нет, собранный
   из самого тега.

Плюс на диске: `~/Downloads/deploy_last_run.log` — построчный итог прогона.

---

## 4. Инварианты

Нарушение любого — дефект, а не «особенность». Каждый закреплён тестом.

| # | Инвариант | Почему |
|---|---|---|
| И1 | Опубликованный тег никогда не переписывается | история версий неизменяема |
| И2 | Существующая репа не разрушается: дерево трогается только после подтверждения маркеров корня (`README.md`, порог файлов) | однажды снесли содержимое репы плоским архивом |
| И3 | Релиз без описания не создаётся | пустой релиз выглядит готовым и не чинится годами |
| И4 | Тег указывает на своё дерево, не на соседнее | git-кэш по mtime врал (PIT-014) |
| И5 | Ничего не удаляется, пока замена не подтверждена на месте | при обрыве связи можно остаться без единственной копии |
| И6 | Осмысленное описание не переписывается без `FORCE=1` | ручной текст ценнее сгенерированного |
| И7 | Повторный прогон на тех же данных ничего не меняет | идемпотентность |
| И8 | Сбой на одной версии или репе не роняет остальные | батч должен доезжать |
| И9 | «Не смог узнать» ≠ «нет»: при сбое связи сущность не считается отсутствующей | иначе скрипт создаёт то, что уже есть |
| И10 | Имена файлов сравниваются буквально, не как регулярки | точка в версии матчила подчёркивание и стирала ассет |
| И12 | Локальный архив удаляется (при `DELETE_AFTER=1`) только после подтверждения тега на remote, релиза и ассета совпадающего размера | иначе удаляется единственная копия |
| И11 | Рабочая папка живёт во временной директории и удаляется при **любом** выходе — нормальном, по ошибке, по Ctrl+C | лежала в `Downloads` и оставалась после каждого прерывания: три забытые папки заняли ~5 ГБ и переполнили диск прямо посреди прогона |

## 5. Таблица решений

Что происходит с найденным в папке архивом:

| Ситуация на входе | Результат |
|---|---|
| Имя по канону, версии на GitHub нет | публикуется полностью (5 пунктов §3) |
| Имя историческое (`_`, `-`, без `v`, `vX.Y`) | публикуется, имя помечается в выводе |
| Имя с хвостом ` copy`, ` 1`, `(1)` | **не** публикуется, названо в выводе как дубль |
| Служебный архив (`files*.zip`, `N.zip`) | пропускается молча, только счётчиком |
| Тег версии уже есть | пропускается |
| Версия ниже старшего тега | пропускается, если нет `BACKFILL=1` |
| Нет `README.md` в корне архива | отказ, репа не трогается |
| `VERSION` внутри ≠ версии в имени | отказ по этой версии |
| Битый zip | отказ, соседние версии публикуются |
| Файлов меньше порога | отказ: это не репа |
| Нет секции в `CHANGELOG` | дерево и тег публикуются, релиз — нет |
| Репы на GitHub нет | создаётся приватной, вносится в `repos-map.md` |
| GitHub не отвечает | репа/версия пропускается с пометкой, не считается отсутствующей |

Что происходит с **уже существующим** релизом (только в режиме ревизии):

| Состояние релиза | Действие |
|---|---|
| Всё по стандарту | ничего, молча |
| Заголовок без тезиса | заголовок пересобирается |
| Тело-заглушка (`Release 1.0.0` и т.п.) | тело берётся из CHANGELOG |
| Тело осмысленное, но ≠ CHANGELOG | не трогается, выводится `~ отличается` |
| Нет канонического ассета | собирается из тега и загружается |
| Есть дубль под старым именем | снимается **после** подтверждения канона |
| Нет секции в CHANGELOG | описание и заголовок сохраняются как есть |

---

## 6. Чего скрипт не делает никогда

- Не переписывает опубликованный тег и не меняет его дерево.
- Не создаёт релиз без описания.
- Не удаляет ничего, кроме дубля архива **той же версии** под старым именем.
- Не публикует рабочие копии и дубликаты.
- Не чинит битую историю тегов молча — только сообщает в блоке «ТРЕБУЕТ ТВОЕГО РЕШЕНИЯ».
- Не трогает локальные архивы: удаление диска — всегда решение человека.

---

## 7. Поведение при отказах

| Отказ | Реакция |
|---|---|
| Сеть моргнула на операции | до 3 повторов с нарастающей паузой, только на транзиентных ошибках |
| Сеть не отвечает дольше `GH_TIMEOUT` | операция прерывается, версия помечается, прогон продолжается |
| `gh` не авторизован | остановка на старте с объяснением |
| Диск заполнен | ошибка копирования видна в выводе, версия помечается |
| Чего-то не хватает для решения | пункт уходит в блок «ТРЕБУЕТ ТВОЕГО РЕШЕНИЯ» |

Правило: **скрипт либо делает правильно, либо не делает и говорит.** Третьего состояния —
«сделал криво и промолчал» — быть не должно.

---

## 8. Как менять поведение

1. **Сначала правится этот файл** — контракт. Если изменение не выражается таблицей
   решений или инвариантом, оно не продумано.
2. **Потом тест** в соответствующей зоне (`tests/README.md`), воспроизводящий новое
   поведение и старое как несоответствие.
3. **Потом код** — режимом внутри `deploy.sh`, никогда отдельным скриптом.
4. **Версия скрипта + запись в `deploy-CHANGELOG.md`.** Смена дефолта — MAJOR:
   команда та же, поведение другое.
5. **Прогон `DRY=1` на реальной папке** — стенд линуксовый, боевая машина macOS,
   класс различий BSD/GNU тестами не ловится.

---

## 9. Границы

Скрипт **не** заменяет: ручной git для повседневной работы в репе, CI, бэкап
(GitHub — не бэкап, а единственная копия после удаления архивов).

Стенд не проверяет: права токена, реальную приватность реп, лимиты GitHub API,
поведение BSD-утилит macOS, рендер markdown в вебе.

---

> **Одной строкой:** на входе — папка с архивами версий, на выходе — GitHub, где у каждой
> версии есть коммит с тезисом, тег на своём дереве, релиз с описанием из CHANGELOG
> и канонический ассет; десять инвариантов охраняют то, что нельзя ломать; всё остальное
> описано таблицей решений, и менять поведение надо начиная с неё.
